# M5.1 erratum -- two clarifications on the original M5 report

This does not overwrite, retract, or delete anything under
`experiments/records/experiment_M5/`. That folder remains the historical
first evaluation, `M5_DETECTION_METRICS.json` and `M5_FINAL_REPORT.md`
unedited. `RAW_PREDICTIONS.json` is reused verbatim by M5.1 -- not
regenerated, not touched.

## A. The Como GT-quality conclusion -- primary vs supporting evidence

`experiments/records/experiment_M5/GT_QUALITY_FINDING.json` and
`M5_FINAL_REPORT.md` are corrected in emphasis (not in their underlying
facts, which stand) as follows:

**Primary evidence** is the known, already-documented annotation-process
mismatch between the three TEST sequences:

- `como_2-0_sassuolo` was annotated in-session by the assistant reading a
  printed coordinate-grid overlay and estimating box corners by eye --
  self-documented throughout `experiments/records/experiment_M4/ANNOTATIONS_DRAFT.json`'s
  per-frame notes as carrying "+/-8-10px" positional uncertainty, and in at
  least one frame (713) explicitly extrapolating an edge from "typical
  player height" rather than the directly observed edge.
- `manchester_city_v_liverpool` and `youth_2` were annotated by direct
  mouse-drag in the purpose-built local browser tool
  (`experiments/records/experiment_M4/local_annotator/`), a fundamentally
  more precise input method with no equivalent failure mode.

This process difference is sufficient on its own to predict a GT-precision
gap between Como and the other two sequences, independent of anything the
detector produced.

**The GT-vs-prediction box-area comparison in `GT_QUALITY_FINDING.json`
is supporting diagnostic evidence only** -- it is consistent with, and
adds numeric texture to, the process-mismatch explanation above. It must
**not** be read as "the detector's predictions prove the GT is wrong":
that framing would be circular (using the very system under test as the
arbiter of its own ground truth's correctness) and is withdrawn as a
primary argument. The primary argument is, and remains, the documented
annotation-method difference.

## B. Number of TEST-touching model executions per sequence in M5

The original M5 final report's compliance section stated "One prediction
pass per sequence; no rerun after results were viewed," in the context of
the "ONE prediction pass per TEST sequence only" hard rule. That statement
is accurate for the **scored** metric pass, but M5 in fact ran **two**
separate executions that touched TEST video/frames per sequence:

1. **The scored raw-detector pass** (`m5_raw_predict.py`): one stateless
   `TwoBranchDetector` forward pass per frame, on exactly the 20 frozen
   `TEST_DETECTION_ANNOTATIONS.json` images per sequence (60 total). This
   produced `RAW_PREDICTIONS.json` and is the only pass any metric was
   computed from.
2. **The E2E structural acceptance run** (`m5_e2e_structural.py`): a
   separate, full-production-pipeline execution (`FootballAnalysisPipeline`,
   including CBIoU tracking, `BallTemporalSelector`, and possession) on 40
   raw frames decoded from each TEST video (reduced to 20 processed frames
   via the production `skip_frames=2` default). This did **not** necessarily
   touch the same 20 frame indices as the scored pass (E2E started from
   frame 0 of each video; the scored frames are the deterministically
   selected `floor((k+0.5)*N/20)` indices) -- it is a structural check, not
   a rescoring of the same frames, and its output (`E2E_ACCEPTANCE.json`)
   was never used to compute or influence any accuracy number.

So the correct count is **two distinct model executions per sequence**,
not one, and the M5 final report's wording claiming a single total TEST
execution per sequence is withdrawn as written. This does **not** invalidate
`RAW_PREDICTIONS.json` or the metrics computed from it: those predictions
were generated exactly once, are frozen, were never tuned, and are **not**
regenerated by M5.1 -- reused verbatim, per the instruction that started
this erratum.

## What M5.1 does next

Prepares a blinded re-annotation queue for the 20 `como_2-0_sassuolo` TEST
frames only (Section 3), to eventually produce a second, independently
re-annotated Como GT that can be compared against the original -- testing
the process-mismatch hypothesis in (A) directly, rather than relying on
inference from the detector's own output. No metric is computed in this
erratum; that is explicitly deferred to after the blinded re-annotation is
complete and the user resumes M5.1.
